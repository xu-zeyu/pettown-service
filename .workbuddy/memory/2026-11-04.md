## Admin 权限功能实现完成（pettown-boot:admin）
- 依赖 jinHan-shop-admin-web 对齐四表模型（admin_account 单角色 role_id / admin_role / admin_permission / admin_role_permission 按编码绑定），测试即契约：AdminAlignmentTests(15) + AdminMigrationTests(2) + AdminSingleRoleMigrationTests(3) + AdminOpenApiTests(2) 全绿，module-business 25 个测试全绿。
- Service 拆分：AdminAccessPolicy（权限解析/越权校验/超管行 FOR UPDATE 锁）+ Account/Auth/Role/Permission 四个 Impl + AdminService 门面纯委托。
- 关键契约（易错，回归时注意）：
  - initializeSuperAdmin：ID=1 空闲时用 ID=1，被普通账号占用时退回自增 ID（测试 setup 每次 @Sql 清表后依赖 id=1）；幂等按 super_admin 存在判断。
  - AdminAccessPolicy.permissions() 只计已启用角色的绑定（停用角色立即失效）；permissionCodesOfRoles（requireManageableAccount 越权校验）故意含停用角色绑定，防借重置/启用接管。
  - ensureSubset 超管直接通过（改码可改成目录外的新编码）；非超管须持有当前+目标编码。
  - selectByRoleIds 传空集合会产生非法 SQL（IN 空括号），调用方必须先短路空列表。
  - 会话：禁用/删除/改密/重置/改手机号 bump sessionVersion；AdminSessionInterceptor.preHandle 先会话校验再 Sa-Token 注解校验。
- docs/sql 四个部署脚本已齐：admin.sql（与 schema.sql 字节一致）、admin-reference-alignment.sql、admin-single-role.sql（标记段供 H2 抽取 + DELIMITER）、admin-test-data.sql（种子过程 pettown_seed_admin_test_data：ID=1 优先、同名非启用超管 SIGNAL 中止、fixture_admin_* 五样例账号）。
- 登录为双因子（密码+短信验证码），无手机号账号不能登录；验证码 key=pettown:verification-code:admin_login:<phone>。
