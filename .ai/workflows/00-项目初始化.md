# 工作流 00：项目初始化与配置核对

用户要求初始化 `.ai` 时，先读取 `../config/workspace.yaml`、`../config/projects.yaml` 和本工作流，确认目标仓库。初始化只覆盖当前明确选定的项目。

1. 先核对当前目录或用户指定目录的可读性、仓库根、构建清单及源码入口，判断它是否为项目。`.ai` 同级的其他目录如果不可读，或没有足够证据证明属于当前项目，直接跳过，不询问、不扫描、不创建配置、不改动该目录。绝不把兄弟目录名当项目 ID。
2. 对确认属于目标项目的目录，执行 `01-项目扫描与画像.md`：看模块边界、入口、依赖、语言/框架/版本、构建测试命令、配置、架构和现有 UI 资源。优先用仓库证据填充注册表、项目 YAML、技术栈画像和知识文件，并注明证据。用户提供的信息标明来源。
3. 无法从目标仓库或已授权连接器确定的必填项，集中向用户询问，尤其是技术栈、项目范围、产品目标、TAPD 空间、Ardot 目标项目和 UI 设计来源。未答复前标记 `待确认`；不得猜填或把项目标记为初始化完成。无关或不适用配置写 `不适用` 并说明原因，不能留空白占位。
4. 前端或客户端项目还须扫描现有设计文件、样式/令牌、组件库、字体、图标、布局、响应式断点、交互/动效、可访问性和平台规范，产出 `../project-knowledge/<项目ID>/ui-guidelines.md`。缺少证据时提出具体问题，用户确认后填写。该文件是原型与 UI Agent 的输入。
5. 核对项目配置的全部字段及 `stack_profiles` 引用、注册表 ID/路径、知识文件路径。运行 `python3 .ai/scripts/check_initialization.py <项目ID>`；它检查关键字段，但不能代替人工核实其真实性。只有当前项目必填字段均有已核实值或明确“不适用”、UI 项目规范完整、项目画像经用户确认后，才将状态设为 `verified`。输出尚待确认清单；不能以模板默认值冒充事实。

注意：本仓库现有 `pet-system` 是后端项目，其他未登记或不可读的同级目录不属于本次初始化范围。
