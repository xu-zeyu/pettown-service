# 工作流 05：开发执行

## 开发前置条件

- 已确认项目 ID 和仓库路径。
- 已获得真实 TAPD 需求 ID。
- 技术方案已经人工批准。
- 任务范围和验收标准清晰。
- 用户已经授权本次代码修改。

## 执行步骤

1. 读取项目配置、相关技术栈配置和已批准的执行方案。
2. 修改前检查 `git status`、当前分支和已有差异。
3. 只有在项目策略允许且用户批准时，才创建或切换功能分支。
4. 遵循项目既有规范，实施最小且完整的代码变更。
5. 为变更行为新增或更新测试。
6. 检查差异，排除无关修改、密钥泄露、不安全日志和兼容性问题。
7. 在环境允许时执行项目配置中确认过的构建、代码检查、类型检查和测试。
8. 记录实际执行命令、退出码、未执行项和失败项。
9. 生成测试报告和交付报告。
10. Git 提交、推送、合并、发布和部署必须等待人工验收及授权。

## 必须暂停并询问的情况

- 需求与现有业务行为冲突。
- 当前仓库不是预期项目。
- 需要执行破坏性数据库迁移。
- 涉及权限、安全边界或敏感数据处理变化。
- 需要引入未经批准的依赖或外部服务。
