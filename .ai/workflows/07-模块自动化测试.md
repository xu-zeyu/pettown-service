# 工作流 07：模块自动化测试（Agent 路由）

用户说"进行 <模块> 的全量测试""测试 <模块>"等指令时，先按本工作流决定使用哪个测试 Agent，再进入对应 skill。本工作流只做路由与通用约束，具体执行见各 skill。

## 1. 路由决策

1. 定位模块：与当前项目 `project-knowledge/<项目>/modules.md` 比对；匹配多个、无匹配或模块边界不清时先核实，不猜测。
2. 依据模块画像（modules.md 中的模块类型、接口清单与仓库证据）选择执行方：

| 模块性质 | 路由目标 |
|---|---|
| 后端 HTTP 接口模块（REST Controller、对外开放 API） | `../skills/api-regression-testing/SKILL.md`（API 测试 Agent） |
| 版本交付中单个需求项的测试 | 跟随版本研发流程，走 `06-测试与交付.md` 的红绿与对抗自测 |
| 纯前端/界面模块 | 暂无对应自动化 Agent，告知用户缺口并询问是否改用人工验收清单 |
| 数据库迁移、中间件、定时任务等非 HTTP 模块 | 暂无对应自动化 Agent，说明缺口，可降级为针对性脚本验证（需单独授权） |

3. 无法确定模块性质时，向用户说明候选并询问，不自行选择。
4. 用户明确指定测试方式（如"用 Apifox 跑"）时，以用户指定为准，仍须满足对应 skill 的授权与门禁。

## 2. 通用约束（所有测试 Agent 适用）

- 测试结果口径与 `06-测试与交付.md` 一致：`通过`/`失败`/`未执行`/`受阻`，如实填写，不把未执行或受阻记为通过。
- 测试目标环境禁止生产地址；执行前确认环境配置。
- 测试产物统一落在 `.ai/runs/` 下对应目录，报告使用 `../templates/测试报告模板.md`。
- 测试中发现疑似缺陷，只记录与报告；创建 TAPD 缺陷、修改代码修复均需单独授权。
- 企业微信通知统一复用 `../skills/tapd-requirement-intake/scripts/send_wecom.py`，按脚本返回码核对，不重复发送。
