# 工作流 02：需求发现与候选需求池

## 目标

围绕一个明确项目，形成有依据、可排序的候选需求。

## 输入来源

- 当前项目 YAML 和项目知识。
- 当前仓库代码、模块地图和技术债务。
- TAPD 历史需求、缺陷和任务（连接器可用且已授权时）。
- 企业微信反馈（连接器可用且已授权时）。
- 用户建议、产品规划，以及用户要求调研的公开竞品资料。

## 执行步骤

1. 确认项目 ID 和产品范围。
2. 阅读项目产品背景和模块地图。
3. 从可用来源收集证据，并记录来源和日期。
4. 与 TAPD 现有事项对比，合并重复反馈。
5. 区分已确认用户痛点、技术债务、产品机会和推测性想法。
6. 根据影响范围、紧急程度、证据可信度、工作量和风险进行排序。
7. 使用 `../templates/需求模板.md` 按版本范围生成候选需求；常规可形成 5–10 条，数量以证据和实际范围为准。
8. 保存到 `requirements/pending/YYYY-MM-DD/`。
9. 向用户展示候选需求、证据、优先级和推荐理由。

## 审批门槛

用户批准前，不得创建正式 TAPD 需求、分配开发人员或修改代码。“生成 <版本> 版本需求”等明确指令按 `../core/人工审批规范.md` 授权该版本的评审、入库和创建通知，无需重复请求同一范围的批准；未确认业务规则仍须标记待确认。
