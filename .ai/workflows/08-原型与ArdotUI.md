# 工作流 08：TAPD 原型与 Ardot UI

## 入口与顺序

“根据 TAPD 需求生成原型/UI”等指令依次调用 `../agents/原型Agent.md` 和 `../agents/ArdotUIAgent.md`，同时加载 `../skills/ardot-ui-delivery/SKILL.md`。本指令授权本地原型与图片产出、已配置 Ardot 项目中的 UI 图片入项及已配置目标的企业微信结果通知；不授权更改 TAPD 需求、产品规则、应用源码或发布。

1. 确认当前项目、仓库和 TAPD 项目空间，实时回读完整需求 ID、标题、状态、必要描述和验收点。只处理用户指定需求，不跨项目套用记录。
2. 读取当前项目架构、产品背景、UI 规范；前端项目必须先完成 UI 规范画像。读取 `.ai/runs/ui/<项目ID>/ledger.json`，按 `项目ID + TAPD空间ID + 需求ID + screen_key` 去重，已生成的屏幕排除。
3. 原型 Agent 先产出页面地图、用户路径、低保真线框、状态及屏幕清单。Ardot UI Agent 再生成图片与设计说明。两者均须结合有日期和来源的最新公开产品体验、竞品、配色与动效资料，并以本项目需求与规范为准；未调研的维度标注未调研。
4. 图片生成后记录 `generated`，保存绝对路径和 SHA-256。调用已核实的 Ardot MCP 工具入项图片，使用真实项目与入项 ID 回读项目归属、文件名/图片及可访问链接，再记录 `imported`。响应不明时先查询 Ardot，不重复入项。
5. 所有本次图片均已入项且回读成功后，复用 `../skills/tapd-requirement-intake/scripts/send_wecom.py` 通知已配置目标。内容包含项目、TAPD ID/链接、屏幕名、Ardot 入项链接、完成与待确认项；按 HTTP 及业务码核对，成功后逐屏记录 `notified`。结果不明先核查，不盲目重发。
6. 在 `.ai/runs/ui/<项目ID>/<需求ID>/` 保存原型、图片、设计说明和回执摘要。三阶段都核对通过，才报告 UI 闭环完成；任何阶段受阻都报告具体阶段和剩余屏幕。

## 约束

- UI 台账是排重线索，TAPD 与 Ardot 实时状态以各自回读为准；台账中的 `generated` 即阻止下次自动重画，失败重试应从失败阶段继续。
- 不在台账、通知或报告中记录令牌、Webhook 或临时下载地址。
- Ardot MCP 的工具名、输入、回读字段及登录方式必须由正式文档或实际工具核实，不能按平台名字猜测。项目 ID 优先从已登录的 Ardot 项目页或 MCP 列表获取并核对项目名。
