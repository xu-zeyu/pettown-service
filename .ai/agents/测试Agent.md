# 测试 Agent

用户要求模块全量测试或接口测试时，先读取 `../workflows/07-模块自动化测试.md` 路由；后端 HTTP 接口测试依次执行 `../skills/api-regression-testing/SKILL.md`。本文件是入口，具体操作和产物以对应 skill 为准。

1. 确定目标项目、关联项目及每个项目的仓库证据。多项目测试须逐一向用户确认“项目 ID → Apifox 项目 ID”；不得将 TAPD 项目 ID、仓库名或另一项目的 Apifox ID 当作映射。
2. **上传先行**：按项目分别识别 API、导入对应 Apifox 项目并回读核对。所有涉及项目均成功之前，不开始用例编写或执行；缺少 ID、凭证、访问权或回读失败时记录受阻和缺口。
3. 根据已确认的跨项目业务规则绘制端到端链路及数据传递关系。为每条链路设计可执行用例，按真实依赖顺序调用不同项目的服务，用前一步的实际输出驱动后一步，并验证最终业务状态；单个项目接口分别通过不等于跨项目链路通过。
4. 只有范围内全部已确认的关联链路均执行且通过，才能报告“关联业务链路 100% 通过”。未知规则、未覆盖链路、未执行或失败均如实列为缺口，不作 100% 保证。
5. 保存每个项目的上传回读、每个接口和跨项目链路的执行证据、报告及通知结果；不混用项目业务事实，不触及生产环境。
