## 真实 Redis 协议自测

在仅绑定 `127.0.0.1:16389` 的临时 Valkey 实例中，从 Java 源文件提取同一 Lua 脚本执行：首请求返回 `0`，同手机号 60 秒内重复返回 `1`，手机号日额满返回 `2`，来源 IP 日额满返回 `3`。对同一 IP 发起 100 次并发请求，恰有 50 次通过、50 次被 IP 日额拒绝。临时服务已停止并卸载；未连接项目配置的外部 Redis。

## 结构化自审

本项无独立审查人，逐文件自审：

- `VerificationCodeController`：新旧路径共用校验与限流；拒绝管理端验证码用途；响应不含验证码且不声称发送短信。
- `RedisVerificationRequestLimiter`：一个 Redis `EVAL` 完成三个额度检查和更新；日界按 Asia/Shanghai；Redis 缺失时拒绝。
- `VerificationClientAddressResolver` 和小程序配置：默认忽略可伪造转发头；仅配置可信代理时使用其覆盖的数值型 `X-Real-IP`。
- `ErrorCodeEnum` / `GlobalExceptionHandler`：限额使用 HTTP 与业务码 `429`；其他错误码行为由全仓测试回归。
- 构建脚本、接口测试及限流测试：复用现有 Redisson 和测试依赖，未引入新第三方；覆盖参数、用途、旧路径、限额、代理来源、Redis 缺失及 OpenAPI。

## 残余风险

- 用户指定的过渡方式要求 Redis 中暂存明文验证码；部署必须限制 Redis 访问。真实短信投递未实现，不应把本项描述为已满足原 TAPD 的短信发送验收。
- 反向代理部署须配置 `PETTOWN_TRUSTED_PROXY_IPS` 并确保代理覆盖 `X-Real-IP`；留空时所有经过同一代理的请求共享该代理的 IP 日额。
- 额度先占用后写验证码；若写验证码失败，额度可能短暂保留，但不会返回成功或泄露验证码。
