## 需求与现状

TAPD 要求 `GET /api/admin/auth/me` 返回账号、角色、权限码，`GET /api/admin/auth/menus` 按权限返回菜单树；不同角色的权限码不同，被停用账号的旧 Token 立即失效。仓库已有 `/mng/auth/me` 和 `/mng/auth/menus`、`MeResponse`、`MenuResponse`、角色权限解析以及逐请求校验账号启用状态和会话版本的 `AdminSessionInterceptor`。现有初始密码流程只允许 `/mng/auth/me`、改密和退出；新路由需保持相同规则。

## 拟定方案

1. 新增只提供两个 GET 的 `/api/admin/auth` Controller，复用现有 `AdminService`、`AccountResponse`、`RoleResponse`、`MeResponse` 和 `MenuResponse`；不对整个旧 `/mng/auth` Controller 增加路径别名，避免把登录、退出、改密等接口一并暴露在新路径。
2. `me` 从管理员 Token 取当前账号 ID，返回实时账号、已启用角色与当前有效权限码排序列表；`menus` 用实时有效权限码生成现有菜单树。无新权限枚举、角色规则、菜单数据库表或存储变更。
3. 新路由不标记 `@SaIgnore`，继续由全局 `AdminSessionInterceptor` 每次请求检查登录、启用状态和会话版本；在初始密码例外路径集合中仅增加 `/api/admin/auth/me`，使新 `me` 与旧路径一致。新 `menus` 在初始密码尚未修改时仍拒绝。停用账号 Token 在这两个新路径上立即失效，重新启用不恢复旧 Token。
4. OpenAPI 文档纳入新路径并标明 Bearer。现有管理端 OpenAPI 测试需允许这两个 TAPD 指定的 `/api/admin/` 路径，其余模块仍保持 `/mng/` 路径。

## 安全、兼容与回滚

不修改旧 `/mng/auth/*` 行为；不建立公开接口。响应复用不含密码哈希和会话版本的 VO。回滚只移除新 Controller 和新增初始密码例外路径，不改账号数据。

## 验收与测试

先写新路径红灯（当前返回 404），再测试：两种角色有效权限码及菜单差异；超级管理员返回全部目录权限；停用后两个新路径均 401、重新启用旧 Token 仍 401；无 Token 和小程序 Token 拒绝；初始密码账号新 `me` 可访问而 `menus` 禁止；旧 `/mng/auth/*` 回归、OpenAPI Bearer 及敏感字段不泄漏。执行全仓 `./gradlew build` 与逐文件审查。
