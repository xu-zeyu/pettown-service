## TAPD 要求与现状

TAPD 要求 `POST /api/admin/system/accounts`，提交用户名、显示名、角色、手机号、初始密码，需 `system:account:create`。用户名唯一、4–50 位字母数字，初始密码满足强度规则，新账号 `password_change_required=true`；验收包括创建后可登录并强制改密，以及用户名重复返回业务错误码。

仓库现有 `POST /mng/system/accounts` 需 `system:account:create`、首次改密但不支持角色；`POST /mng/create` 支持角色但需 `SUB_ADMIN`、新账号不强制首次改密。两者的用户名校验为 3–50 位小写字母/数字/下划线、以字母开头；密码仅要求 8–72 位非空格 ASCII。数据库 `admin_account.username` 已有唯一约束，`role_id` 已存在；重复键目前统一返回业务码 `400` 和“管理员账号已存在”。

## 拟定方案

1. 在已有 `/api/admin/system/accounts` 只读 Controller 中精确新增 `POST`，不对整个旧 Controller 加路径别名。新 POST 使用 `@SaCheckPermission(system:account:create, type="admin")` 与全局 ADMIN 会话拦截，记录创建操作日志；匿名、小程序 Token 无权访问，初始密码未改的管理员无法创建。
2. 独立请求 DTO：`username` 为 4–50 位 ASCII 字母或数字；`displayName` 非空、最多 50 字；`roleId` 可选正整数；`phone` 可选、为 11 位中国大陆手机号；`password` 为初始密码，8–72 位非空格 ASCII，且至少包含字母、数字、符号三类（明确本项“强度规则”）。密码只入参，OpenAPI 标记 writeOnly；响应为既有不含密码字段的 `AccountResponse`。
3. 业务层新增专用于 v1 的 `createV1Account`：在现有串行写入权限校验和事务内验证输入；有角色时要求角色存在且其权限为操作者当前权限子集，防止越权授予；使用现有 `insertNewAccount` 保存哈希、`enabled=true`、`superAdmin=false`、`passwordChangeRequired=true`、`sessionVersion=0` 和角色绑定。旧 `/mng` 创建方法保持原行为。
4. 对新 POST 的用户名重复（含并发唯一约束冲突）返回明确业务码 `4091`、HTTP 409、消息“管理员账号已存在”；旧接口原有错误码不变。数据库唯一约束为最终仲裁，避免先查后插竞态。新业务码只在此接口使用。
5. `springdoc.paths-to-match` 已精确包含 `/api/admin/system/accounts`，本项只需新增 POST 的 Bearer、权限描述及 DTO 文档，不扩大其他路径。
6. 新格式允许大写字母和纯数字用户名；为使新账号可登录，`LoginRequest` 同时接受旧小写/下划线格式和新的 4–50 位字母数字格式，不放宽旧账号创建接口。
