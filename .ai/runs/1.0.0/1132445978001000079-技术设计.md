## TAPD 验收与仓库现状

TAPD 要求 `POST /api/miniapp/files/upload`（或 OSS 直传签名），仅登录用户可传 `jpg/png/webp`，单张不超过 5 MB，返回可访问 URL；每用户每天最多 50 张，超尺寸、非法格式和匿名请求须被拒绝。TAPD 同时标记 OSS 厂商、bucket 配置和图片内容审核通道待确认。

仓库已有 `common-file` 中的阿里云 OSS SDK 和 `OssFileService`，但由 `pettown.file.enabled=true` 才启用；小程序尚未依赖/启用该模块，现有实现返回桶的公开地址，不能保证私有桶可读。小程序运行配置已有 OSS 环境变量占位符，未确认真实桶及费用。小程序已有 USER Bearer 拦截器和 Redis/Redisson 限流模式，测试使用 H2 且禁用 Redis。

## 已确认方案

1. 接入现有 `common-file` 阿里云 OSS 模块，只使用私有桶，不让客户端直传或直接读取 OSS。`POST /api/miniapp/files/upload` 接受 multipart 字段 `file`，将图片保存为 `miniapp/images/<UUID>.<ext>`，返回由部署配置的 `PETTOWN_FILE_PUBLIC_BASE_URL` 拼接的应用绝对 URL。`GET /api/miniapp/files/{fileId}` 每次要求有效 USER Bearer 会话，由应用从私有 OSS 读取并以已验证的图片 Content-Type 返回；任何已登录小程序用户持有 URL 均可读取，匿名/ADMIN Token 不可读。存储对象名称由随机 ID 构造，不使用原始文件名或用户提供的路径。用户最终选择了代理读取，因此不向客户端暴露临时 OSS 签名 URL。
2. 服务端校验非空图片、扩展名与文件头一致，格式限 jpg/jpeg、png、webp，大小不超过 `5 * 1024 * 1024` 字节。公共基址必须是明确配置的 `https` 地址（测试环境可用 `http://localhost`），避免信任可伪造的 Host/Forwarded 头生成 URL。GET 设置正确图片类型和 `X-Content-Type-Options: nosniff`。
3. 通过 Redis 原子计数按上海自然日限制每用户成功上传最多 50 张；存储失败时归还当日额度。Redis 不可用时拒绝上传，不能无上限放行。测试用替身文件服务和限额服务，不使用真实 OSS 凭证。
4. 本版不接入尚未确定的内容审核通道；图片只经 USER 会话保护的应用接口读取。真实 OSS bucket、访问密钥和权限由部署环境提供，不写入代码；没有配置时上传失败并说明服务不可用。私有桶配置和真实网络可达性需用户在部署前验证。
