# 技术设计：1132445978001000068 — 小程序手机号登录与首次注册

- 项目 ID：`pet-system`

- 编写日期：2026-11-05

## 一、需求摘要

现有手机号、密码、验证码登录及首次注册保持可用；验证码错误、密码错误、参数缺失有不同业务码；连续 5 次密码错误锁定 15 分钟；用户 token 有效期 7 天。不得因已注册用户密码错误创建新账号。

## 二、现有实现分析

`AuthController` 已提供 `POST /api/miniapp/auth/login` 并返回用户 ID、手机号和 token；`UserAuthServiceImpl` 先一次性消费验证码，再查手机号，已注册用户校验密码，未注册用户创建账号。密码错误和验证码错误目前共用通用业务码 `400`；未做密码失败锁定。小程序 `sa-token.timeout` 默认 30 天。

## 三、建议技术方案

1. 保留现有注册并发去重及验证码一次性消费。已注册账号先检查锁定，再校验验证码及密码；密码校验失败时以 Redis 原子计数累计该手机号的错误次数，达到 5 次进入 15 分钟锁定；成功登录清零。Redis 故障时不绕过锁定机制。
2. 为参数、验证码、密码错误和锁定设置独立业务码，并保持 HTTP 状态语义；不在响应或日志暴露密码与验证码。锁定信息仅在验证码验证后公开，避免匿名探测账号是否存在。
3. 小程序令牌有效期改为 7 天；确认当前 Sa-Token 会话创建方式及已有令牌兼容性后实施。

## 六、权限与安全考虑

入口匿名；失败计数以服务端 Redis 原子操作实现，不信任客户端计数。锁定窗口、验证码消费顺序和账号存在性须由测试覆盖。密码和验证码不写日志。

## 七、兼容性与数据迁移

无数据库迁移。7 天令牌配置可能影响变更前已签发令牌；上线前核对 Sa-Token 实际生效范围。

## 八、异常处理与可观测性

记录失败类别计数，不记录凭证内容；Redis 不可用时认证失败并返回稳定错误，不静默放行。
