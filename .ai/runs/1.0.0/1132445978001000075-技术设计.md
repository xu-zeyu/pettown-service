## 需求与现状

TAPD 要求 `PUT /api/miniapp/pets/{id}`，仅宠物归属人可编辑，字段校验同创建；本人编辑生效，非本人请求拒绝且不改数据。现有小程序创建 DTO 校验名称、英文物种及可选字段范围，详情接口以 ID 和登录用户归属共同过滤；`pet` 已有对应字段和 `updated_time`。

## 拟定方案

1. PUT 请求复用 `CreatePetProfileRequest` 验证完整档案：`name`、`species` 必填，可选字段按请求值覆盖，显式 `null` 清空旧值；请求体额外 `ownerId` 不参与更新。
2. 使用既有 `PetTownToken.USER` 取得登录用户 ID；单条 SQL 更新以 `id` 与 `owner_id` 同时作为条件，设置可编辑字段及 `updated_time`，不修改 `id`、`owner_id`、`created_time`。更新后按相同归属条件回读，查不到时使用现有 `NOT_FOUND`（HTTP 404，“宠物不存在”），不暴露他人记录是否存在；也避免数据库驱动把重复写入计作 0 行时误报 404。
3. 在事务中更新后按同样的 `id + owner_id` 条件回读完整档案，响应复用 `PetProfileResponse`。不新增数据库列、依赖或外部服务；不修改 App 端接口。
