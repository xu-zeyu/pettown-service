## TAPD 验收与现状

TAPD 要求 `GET /api/admin/system/accounts`，分页并按用户名、显示名、状态、角色筛选；必须具有 `system:account:read`，无权限角色返回 403。现有 `GET /mng/system/accounts` 已使用该权限码、`PageParam` 分页、账号或显示名的 `keyword` 模糊查询及 `enabled` 筛选，返回不含密码哈希、会话版本的 `AccountResponse`。业务层按 ID 升序并在 SQL 层分页，当前没有角色筛选。

## 拟定方案

1. 仅新增一个 `GET /api/admin/system/accounts` 控制器；不用整个旧 `AdminAccountController` 的前缀别名，防止把创建、编辑、删除等写接口暴露到新路径。
2. 查询参数：`page` 默认 1、`size` 默认 10，遵循现有 `PageParam` 的 `page≥1`、`size=-1` 或 1–1000 校验；`username`、`displayName` 分别进行去首尾空格后的模糊匹配，两者同时传入时取交集；`enabled` 为可选布尔值；`roleId` 为可选正整数，精确匹配账号当前关联角色 ID。未传的条件不限制；不存在的角色 ID 返回空列表及 `total=0`，不要求角色仍启用。返回原有 `PageResult<AccountResponse>`，稳定按账号 ID 升序排序。
3. 业务层增加专用于该查询的筛选方法，在 `admin_account` 查询中组合条件并于数据库分页；保留旧 `listAccounts(page, keyword, enabled)` 行为不变。角色绑定现有 `admin_account.role_id` 字段，无新表或迁移。
4. 新 GET 标记 `@SaCheckPermission(system:account:read, type="admin")`，不标记 `@SaIgnore`；仍由全局 `AdminSessionInterceptor` 先检查 ADMIN Token、账号启用状态、会话版本及初始密码改密要求。无 Token、小程序 Token 返回 401；有效但缺权限返回 403；初始密码未修改返回 403。`springdoc.paths-to-match` 精确增加此路径并声明 Bearer。
