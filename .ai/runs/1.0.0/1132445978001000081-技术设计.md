## TAPD 验收与仓库现状

TAPD 要求 `GET /api/admin/verification/captcha` 返回验证码 ID 与图片（Base64），5 分钟有效、一次性，同一 IP 每分钟限 20 次；验收为「返回验证码 ID+图片，校验一次后失效」。

仓库现状：管理端旧接口在 `/mng/**`（短信验证码登录），与 v1.0.0 的 `/api/admin/**` 路径不冲突；admin 拦截器公开接口以 `@SaIgnore` 标注；测试环境 Redis 禁用。仓库无图形验证码实现，也未批准引入新依赖。

## 方案

1. `GET /api/admin/verification/captcha`（`@SaIgnore` 公开）：响应 `CaptchaResponse(captchaId, imageBase64)`。验证码为 4 位随机字符（`A-Z2-9` 去除易混字符 `0/O/1/I/L`），用 JDK `BufferedImage` 绘制 120x40 PNG（干扰线+旋转字符）并 Base64 编码；**不引入任何新依赖**。
2. 存储与一次性语义：`CaptchaStore.save(id, code)` 写入 Redis（键 `pettown:admin-captcha:<uuid>`，TTL 300 秒）；`CaptchaStore.pop(id)` 以 Lua 原子「读取并删除」实现一次性——**无论校验成功与否，ID 一经消费即失效**（防同票多次猜测）。`AdminCaptchaService.consume(id, code)`（不区分大小写比较）供 ADMIN-V1-02 登录调用，本项以单元测试固化一次性与过期语义。
3. 限流：`CaptchaRateLimiter.checkAndRecord(ip)` 以 Lua 原子计数，键 `pettown:admin-captcha-rate:<ip>:<yyyyMMddHHmm>`（上海时区分钟桶），每分钟最多 20 次，超出返回 429。客户端 IP 仅在直连地址为配置的受信代理时才采用 `X-Real-IP`（`pettown.admin.captcha.trusted-proxy-ips`），防匿名伪造来源绕过限流。
4. Redis 不可用时拒绝签发（503 服务暂不可用），不放行无限额验证码。测试使用替身存储与限流器；Redis Lua 语义用 mock Redisson 单元测试验证。

## 测试、交付与边界

- 红灯：`AdminCaptchaApiTests` 覆盖返回 ID+可解码 PNG、两次签发 ID 不同、同 IP 第 21 次 429、伪造 X-Real-IP 不能绕过限流；`AdminOpenApiTests` 操作数 56→57 且新接口为公开。单元测试覆盖：码字符集/长度、Base64 PNG、consume 一次性（对/错码均失效）、过期失效、限流键与 TTL、Redis 缺失拒绝。
