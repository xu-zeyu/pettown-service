## TAPD 验收与仓库现状

TAPD 要求 `GET /api/miniapp/home/summary` 一次返回宠物数量、宠物卡片摘要（头像/名称/物种）、未来 7 天健康提醒数，数据按归属用户隔离；验收为「一次调用返回首页所需数据；无宠物用户返回空集合而非报错」。

仓库现状：`pet`、`pet_health_record` 表与 Mapper 均已具备（含 `@TableLogic` 软删过滤），`PetHealthRecord.nextReminderDate` 支持提醒日期；无首页聚合接口。

## 方案

1. 新增 `GET /api/miniapp/home/summary`（USER 会话保护），响应 `HomeSummaryResponse(petCount, petCards[], upcomingReminderCount)`；`petCards` 每项含 `id、name、species、avatarUrl`（头像/名称/物种 + 卡片定位所需 id）。
2. 查询下推 SQL：宠物列表按 `owner_id = 当前用户` 过滤（软删自动排除）；提醒数按 `pet_id IN (本用户宠物)` 且 `next_reminder_date` 落在提醒窗口内计数，软删记录自动排除，`next_reminder_date` 为 NULL 不计入。宠物为空时跳过 IN 查询并返回 0。
3. 提醒窗口口径：自今天起 7 天（含今天，即 `[今天, 今天+6]`），按上海时区取今天；该口径为实现默认值，**待产品确认**，如需改为「今天至第 7 天」可调整一处常量。
4. 无宠物用户：`petCount=0`、`petCards=[]`、`upcomingReminderCount=0`，不报错。
