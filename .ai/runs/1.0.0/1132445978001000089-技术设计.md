## TAPD 要求与现状

TAPD 要求 `/api/admin/system/roles` 的列表、创建、编辑、删除（软删），按 `system:role:*` 权限控制；角色 `code` 唯一，已被账号引用时禁止删除并提示引用数量。仓库现有 `/mng/system/roles` 有分页、详情、编辑与删除，创建在旧 `/mng/role/create`，创建编码由服务生成；旧删除会清除账号绑定和角色权限，不检查引用数。`admin_role.deleted` 已存在并由 `@TableLogic` 处理，`admin_account.role_id` 为单角色绑定，账号也已采用软删。

## 拟定方案

1. 新增独立 `/api/admin/system/roles` Controller，只映射 `GET /`、`GET /{id}`、`POST /`、`PUT /{id}`、`DELETE /{id}`。分别要求 `system:role:read`、`read`、`create`、`update`、`delete`；不加 `@SaIgnore`，沿用全局 ADMIN 会话与初始密码改密门槛。旧 `/mng` Controller 不做路径别名。
2. 列表复用现有 `PageParam` 与 `listRoles`：`page` 默认 1、`size` 默认 10（`-1` 查询全部）、`keyword` 按编码或名称模糊匹配、`enabled` 可选；按角色 ID 升序。详情、列表和创建响应使用新安全 VO，包含 `id/code/name/description/enabled/createdTime/updatedTime`，不返回已软删角色。
3. 新增 `createV1Role(actorId, code, name, description)`：`code` 为 3–50 位小写字母、数字或下划线且以字母开头，创建后不可修改；`name` 非空最多 50 字，`description` 可选最多 500 字；默认启用。数据库唯一约束仲裁并发重复编码，返回 HTTP 400 及“角色编码已存在”；已软删编码仍保留，不复用。要求 `system:role:create`。
4. 新增 `updateV1Role(actorId, id, name, description, enabled)`：全量更新名称、说明及启用状态，要求 `name` 非空最多 50 字、`enabled` 必填；`description=null` 通过显式 SQL `SET` 清空说明，避免 MyBatis 默认忽略 null；`code` 不接受修改。要求 `system:role:update` 和现有不可编辑自身角色、不得越权管理角色的策略。禁用角色后其权限对后续请求立即失效。
5. 新增 `deleteV1Role(actorId, id)`：在现有串行化写权限事务内要求 `system:role:delete` 和可管理角色；统计未软删账号中 `role_id=id` 的数量。大于 0 时返回 HTTP 400，消息包含准确引用数（如“角色已被 2 个账号引用，不能删除”），不更改角色或账号；为 0 时清理角色权限并 `@TableLogic` 软删角色。已软删账号不计入活动引用；旧 `/mng` 删除契约保持原行为。
6. SpringDoc 精确收录这两种新路径，声明 Bearer、各权限码和请求字段；不新增数据库结构、依赖或外部服务。
