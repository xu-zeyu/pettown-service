## TAPD 要求与现状

TAPD 要求新增 `POST /api/miniapp/auth/logout`，使当前 Token 立即失效；验收为原 Token 再访问任一受保护接口返回未登录。现有 `AuthController` 只有公开的登录 POST；小程序 `MiniappUserSessionInterceptor` 已要求受保护方法持有有效 USER Token，且逐请求检查用户状态。Sa-Token USER 与 ADMIN 使用独立空间；小程序仅从 Authorization Bearer 请求头读取 Token。

## 拟定方案

1. 在现有 `AuthController` 增加唯一新路由 `POST /logout`，无请求体、未标注 `@SaIgnore`，方法级 OpenAPI Bearer 声明。依靠现有小程序拦截器先验证 USER 会话及 ACTIVE 账号，然后对**当前请求 Token**调用 `PetTownToken.USER.logout()`，返回统一成功响应。
2. 不按用户 ID 批量注销，不改变管理员 Token；无 Token、已失效 Token、ADMIN Token 再调用本路由均返回 401。相同 Token 第二次退出也返回 401。登录、验证码和其他接口契约不变。
3. SpringDoc 新增该操作，操作总数由 10 变为 11。先做新路径 404 红灯，再验证退出成功、旧 Token 访问 `/api/miniapp/user/me` 和宠物接口均 401、二次退出 401、匿名与 ADMIN Token 401，以及登录后新 Token 正常。运行全仓 `./gradlew build`、差异检查及逐文件结构化自审。
