## TAPD 验收与仓库现状

TAPD 要求 `PUT /api/miniapp/user/profile` 支持修改昵称（1-20 字、敏感词过滤）与头像 URL（必须为本系统上传接口返回），仅可修改本人资料，`user_account` 增加 `nickname`、`avatar` 列；验收为「修改后 me 返回新值；昵称超长/为空返回参数错误」。

仓库现状：`UserController.me` 仅返回 `userId/phone`；`User` 实体无昵称头像字段；4 份 H2 测试 `schema.sql` 与 MySQL 增量脚本均无对应列；图片上传接口（MINIAPP-V1-13）刚交付，上传响应 URL 形如 `{PETTOWN_FILE_PUBLIC_BASE_URL}/api/miniapp/files/{fileId}`。

## 方案

1. `user_account` 增列 `nickname VARCHAR(20) NULL`、`avatar VARCHAR(2048) NULL`：同步更新 miniapp/app/admin/module-business 四份 H2 测试结构；MySQL 交付幂等增量脚本 `docs/sql/user-account-profile-v1.0.0-alter.sql`，由用户核对后手工执行，本仓库不自动迁移。`User` 实体新增 `nickname`、`avatarUrl`（映射 `avatar_url`）。
2. `PUT /api/miniapp/user/profile` 接收 `{nickname?, avatarUrl?}` 部分更新，路由由 USER 会话拦截器保护，仅更新当前登录账号（接口不接受用户 ID，杜绝越权）。两字段均为 null 时返回参数错误。
3. 昵称校验：去首尾空白后 1-20 字；命中内置敏感词初版词库即拒绝（词库为起始集，待产品提供完整词库后扩充，标记待确认）。头像校验：URL 必须为 `{已校验的 publicBaseUrl}/api/miniapp/files/{fileId}` 且 fileId 为 `UUID.扩展名`（jpg/png/webp），即只接受本系统上传接口返回的地址；本版不回查 OSS 存在性，避免额外存储调用。`publicBaseUrl` 缺失或不合规时拒绝头像修改并说明服务未配置。
4. 为满足「修改后 me 返回新值」验收，`GET /api/miniapp/user/me` 响应扩展 `nickname`、`avatarUrl` 两字段（完整资料字段由 MINIAPP-V1-03 收口，不在本项扩张）。
