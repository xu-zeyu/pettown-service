## 需求与验收

`GET /api/miniapp/pets?page=&size=` 只返回当前登录用户的宠物，按创建时间倒序分页，响应含 `list`、`total`。用户 A 不可见用户 B 的数据；非法分页参数退回默认值。

## 现状与方案

- 前一项已有小程序创建接口、`PetMapper`、完整档案响应 `PetProfileResponse`，宠物表有 `owner_id`、`created_time`，无需结构变更。
- 在已有 `MiniappPetController` 添加 GET；沿用 `PetTownToken.USER` 取登录用户 ID，服务查询必须在 SQL 的 `WHERE owner_id = ?` 过滤，而不是查出后再过滤。
- 使用既有 MyBatis Plus 分页插件和 `PageResult`，默认 `page=1,size=10`。页码只接受正整数，页大小只接受 1–1000；缺失、非数字、溢出和越界值各自回退该字段默认值。`size=-1` 在本接口不提供全量查询。
- `ORDER BY created_time DESC, id DESC`，同时间以 ID 稳定排序。响应复用完整宠物档案 VO，不改变 App 端接口。

## 安全、兼容与回滚

沿用既有小程序 Bearer 登录校验；不接收客户端 ownerId。未登录拒绝。无数据时返回空列表与 `total=0`。回滚仅移除此 GET 路由和列表服务方法，不涉及数据迁移。

## 风险与假设

TAPD 未指定默认分页值和最大页大小，采用仓库 `PageParam` 的 1/10 与 1000 上限；这一选择只影响分页保护，不新增业务规则。若产品之后指定不同限制，可调整查询参数解析。跨请求新增宠物时 offset 分页可能出现重复或跳项，当前需求不要求游标分页。
