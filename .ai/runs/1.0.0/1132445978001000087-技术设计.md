## TAPD 要求与现状

TAPD 要求 `PUT /api/admin/system/accounts/{id}/status`（`system:account:status`）及 `DELETE /api/admin/system/accounts/{id}`（`system:account:delete`，软删）。不可停用/删除自己及超级管理员；停用使账号全部旧 Token 失效，且无法再登录。

仓库已有 `/mng/system/accounts/{id}/status` 与 `DELETE /mng/system/accounts/{id}`，分别使用上述权限码。现有服务会拒绝操作自己/超管，状态变更递增 `session_version`；旧 `DELETE` 会物理删除，`admin_account` 尚无软删除列。`AdminSessionInterceptor` 逐请求复查账号和会话版本；旧删除 Controller 还会调用 `PetTownToken.ADMIN.logout(id)`。

## 拟定方案

1. 为 `admin_account` 增加 `deleted INT NOT NULL DEFAULT 0`，在 `AdminAccount` 标记 MyBatis-Plus `@TableLogic`。实体通用查询自动忽略已删除账号，现有 `deleteAccount` 的 `deleteById` 转为逻辑删除；旧 `/mng` 删除路径的可见效果保持一致。已软删除的用户名继续受现有唯一约束保留，不自动释放或复用。
2. 提供增量 SQL `docs/sql/admin-account-soft-delete-v1.0.0-alter.sql`，更新新库 DDL `docs/sql/admin.sql`、测试结构及旧库整体对齐脚本与测试副本；只编写脚本，由用户后续执行，不连接或迁移运行库。迁移前应用不能在旧表结构上运行新版实体；交付记录明确执行顺序。
3. 在已有 `/api/admin/system/accounts` Controller 中精确新增 `PUT /{id}/status` 和 `DELETE /{id}`，分别使用 `@SaCheckPermission(system:account:status)`、`@SaCheckPermission(system:account:delete)`，复用现有 `StatusRequest`、`setAccountEnabled`、`deleteAccount`，不别名化整个旧 Controller。新路径受 ADMIN 会话拦截和初始密码改密门槛。停用后除现有 `session_version` 递增外，主动 `logout(id)` 注销该账号会话；删除后同样注销。重新启用不恢复旧 Token。
4. 拒绝操作自己、超管或授权超出操作者范围的账号，沿用现有业务错误；不存在或已删除账号返回 404。账号列表、详情、登录和权限解析均排除已软删除账号；角色及角色权限不删除。
5. OpenAPI 精确记录两项方法、Bearer 与权限码；不新增权限枚举、新依赖或外部服务。
