## 需求与现状

TAPD 要求 `GET /api/miniapp/pets/{id}/health-records?type=&page=&size=`，按记录日期倒序，支持类型筛选；分页及筛选正确，越权访问返回“不存在”。前一项已有 `pet_health_record` 实体、Mapper、类型枚举、响应 VO 和新表待执行 SQL，当前项无需数据库结构变更或新依赖。

## 拟定方案

1. 沿用小程序 Bearer 登录态取 ownerId；服务先用 `pet.id + pet.owner_id` 查询目标宠物，不存在及非本人统一抛 `NOT_FOUND`（HTTP 404、“宠物不存在”），然后仅按该宠物 ID 查询健康记录。整个读取使用只读事务，避免不同请求状态混杂。
2. 可选 `type` 只接受 `VACCINE/DEWORM/WEIGHT/OTHER`；缺失或空值不筛选，非法值返回 400。使用现有 MyBatis Plus 分页与 `PageResult`，按 `record_date DESC, id DESC` 排序，同日记录稳定排序。
3. 为与已有小程序宠物列表一致，默认 `page=1,size=10`；缺失、非数字、溢出或越界的分页值各自退回默认值；大小 1–1000，`size=-1` 不提供全量读取。响应含完整记录 `list` 与 `total`，无记录时空列表和 0。
4. 路由加 OpenAPI Bearer 声明，复用上一项 `PetHealthRecordResponse`。不修改创建接口、App/admin 路由或表结构。

## 安全、兼容与回滚

宠物归属校验在记录查询之前完成，不接收客户端 ownerId；他人宠物与不存在宠物返回相同错误，不暴露健康记录是否存在。回滚仅移除 GET 路由和列表服务方法，不迁移数据。运行库仍需用户执行上一项的新表 SQL 才能实际使用。
