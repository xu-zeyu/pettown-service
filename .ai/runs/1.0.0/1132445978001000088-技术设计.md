## TAPD 要求与现状

TAPD 要求 `POST /api/admin/system/accounts/{id}/reset-password`，需 `system:account:reset-password`；`POST /api/admin/auth/change-password` 供本人改密并校验旧密码。重置后 `password_change_required=true` 且旧会话失效；密码 8–64 位且包含字母和数字。验收：被重置账号下次登录必须改密，改密后旧 Token 失效，弱密码拒绝。

仓库已有 `PUT /mng/system/accounts/{id}/password` 与 `PUT /mng/auth/password`，对应服务会校验权限/旧密码、更新密码哈希、修改 `passwordChangeRequired`、递增 `sessionVersion`；初始密码账号仅可访问旧 `/mng/auth/password` 等本人路径。现有密码规则为 8–72 位非空格 ASCII，与本项 TAPD 的 8–64 位且字母+数字不同。

## 拟定方案

1. 在新账号 Controller 精确增加 `POST /api/admin/system/accounts/{id}/reset-password`，使用 `@SaCheckPermission(system:account:reset-password, type="admin")`、全局 ADMIN 会话拦截与操作日志。复用既有“不得重置自己、超管或权限超出自身的账号”策略。成功后 `passwordChangeRequired=true`、会话版本递增，并主动注销目标账号全部 Token；密码不出现在响应中。
2. 在新 `/api/admin/auth` Controller 精确增加 `POST /change-password`，不增加 `@SaIgnore`；从 ADMIN Token 取本人 ID，验证旧密码，拒绝与旧密码相同的新密码；成功后 `passwordChangeRequired=false`、会话版本递增并注销本人所有旧 Token。仅将此新路径加入初始密码账号可访问例外集合，其他管理接口继续禁止。
3. 新接口各用独立 DTO，字段与旧接口一致：重置使用 `password`，本人改密使用 `oldPassword`、`newPassword`。新密码统一要求 8–64 位非空格 ASCII 且至少包含一个字母、一个数字；符号允许但不强制，服务层在事务内再次校验。原密码仅校验非空。旧 `/mng` 路由与原 8–72 位规则保持不变。
4. OpenAPI 精确收录两条新路径，标注 Bearer、权限与密码 writeOnly；不新增数据库列、依赖或外部服务。
