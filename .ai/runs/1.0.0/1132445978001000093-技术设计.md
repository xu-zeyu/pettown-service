# TAPD 1132445978001000093 ADMIN-V1-13 C 端用户宠物数据查看接口 技术设计

- 需求：GET /api/admin/users/{id}/pets 只读查看指定 C 端用户宠物列表与数量（不含健康记录明细），需 `biz:user:read`；响应不含 passwordHash 等敏感字段。验收：返回该用户宠物列表与移动端数据一致；不含敏感字段。
- 端：pettown-boot/admin（管理端）。前置 ADMIN-V1-12（C 端用户管理）、MINIAPP-V1-06（宠物档案）均已完成，`pet` 表已有生产 DDL（docs/sql/pet-v1.0.0-create.sql + 增量），本项无迁移 SQL。

## 接口契约

`GET /api/admin/users/{id}/pets`（登录态 + `biz:user:read`，type=admin）：

```json
{
  "code": "200",
  "data": {
    "userId": "pettown_user_a",
    "petCount": 2,
    "pets": [
      {
        "id": 10, "ownerId": "pettown_user_a", "name": "豆豆", "species": "CAT",
        "breed": "英短", "gender": "FEMALE", "birthDate": "2024-01-05",
        "weightKg": 4.20, "sterilized": true, "avatarUrl": "https://cdn/x.png",
        "createdTime": "2026-11-01T10:00:00", "updatedTime": "2026-11-02T10:00:00"
      }
    ]
  }
}
```

- 宠物条目字段与移动端 PetProfileResponse 完全一致（id、ownerId、name、species、breed、gender、birthDate、weightKg、sterilized、avatarUrl、createdTime、updatedTime），排序与移动端列表一致（createdTime 倒序、id 倒序），保证「与移动端数据一致」。
- `petCount` 为该用户未软删宠物总数，等于 pets.size()（单用户上限 20，不分页）。
- 响应不含 passwordHash、用户手机号等敏感字段，不含 pet_health_record 明细。

## 实现

- `module-business`：AdminUserService 增 `List<Pet> listUserPets(String userId)`：
  - 先 `getUser(userId)`（不存在抛 NOT_FOUND「用户不存在」，与用户详情口径一致）；
  - PetMapper 按 owner_id 过滤 + @TableLogic 自动排除软删，orderByDesc(createdTime)、orderByDesc(id) 与移动端一致。
- `module-admin`：`user/vo/AdminUserPetsResponse`（userId、petCount、pets）嵌套条目记录，静态 from(User id, List<Pet>)；`UserController` 增 `GET /{id}/pets`，`@SaCheckPermission(USER_READ, type=admin)` 与用户详情同权限。

## 风险与边界

- 只读接口，无并发写风险；查询下推 SQL（owner_id 索引 idx_pet_owner_id）。
- 单用户宠物 ≤20（创建约束），全量返回无需分页。
