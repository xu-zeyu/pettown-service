# AI 研发运行原则

## 1. 项目上下文解析

1. 确定本次任务的项目 ID。
2. 读取 `config/workspace.yaml` 和 `config/projects.yaml`。
3. 读取当前项目对应的 YAML 配置。
4. 核对仓库根目录和 Git 工作区。
5. 只读取当前项目所需的技术栈配置及项目知识。
6. 如果项目选择或仓库身份不明确，停止操作并询问用户。

## 2. 事实与证据

- 明确区分仓库事实、用户提供的信息、假设和建议。
- 技术结论尽量附带文件路径、命令或实际执行结果。
- 未知信息统一标记为 `待确认`。
- 不得编造模块、接口、数据库表、TAPD 编号、Skill 名称、测试结果或发布状态。

## 3. 代码变更纪律

- 研发任务先读取 `agents/研发Agent.md`。编写代码前必须读取当前项目的架构、项目与技术栈配置、适用约束，并从仓库核实相关源码、构建和测试入口。
- 修改前检查 Git 状态、当前分支和已有差异。
- 每个需求在独立功能分支开发；不得在默认分支直接开发或混入其他需求。
- 大范围修改前，先说明涉及文件、修改目的和风险。
- 变更范围必须与当前项目和已批准需求一致。
- 遵循项目已有编码规范，不擅自引入新架构。
- 先以测试复现缺失行为或缺陷（红灯），再实现并通过测试（绿灯）；执行与变更风险相符的对抗自测。
- 开发完成后必须代码审查，修复并复审所有未解决问题；必需测试、对抗自测和审查全部通过后才可合并分支。
- 只运行项目配置中存在或已从仓库核实的命令。
- 报告测试时明确区分：通过、失败、未执行、受阻。

## 4. 多项目协作

- 未经用户明确要求，不得跨项目读取业务知识。
- 跨项目任务必须分别记录项目 ID、仓库路径和执行结果。
- 不得把一个项目的业务规则当成另一个项目的事实。
- 不同仓库的代码修改和执行记录必须分开。
