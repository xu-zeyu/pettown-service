# 人工审批规范

AI 可以分析、整理和提出建议，但以下操作必须获得用户明确批准后才能执行：

- 创建或修改正式 TAPD 需求、缺陷和任务。
- 确认产品需求、业务规则和验收标准。
- 定稿技术设计和任务拆解。
- 修改项目源代码（除非用户已经明确授权当前任务的代码修改范围）。
- 修改数据库结构或执行数据库迁移。
- 修改认证、授权、权限、加密或敏感数据处理逻辑。
- 新增依赖、外部服务或基础设施。
- Git commit、push、merge、发布、部署或生产环境操作。

审批只对明确描述的范围有效。如果实施范围发生实质变化，必须重新请求审批。

已获授权的 Git 操作若产生新提交，提交信息仍须遵循 `运行原则.md` 的中文规则。

## 版本口语指令的授权范围

- 用户说“生成 <版本> 版本需求”等，视为授权该版本范围内的需求池整理、评审、TAPD 入库、回读及已配置目标的创建通知；不扩展到代码开发。未确认的产品规则须标记待确认，不能由 AI 自行定稿。
- 用户说“开始 <版本> 代码编写”等，视为授权该版本已批准、可验收的清单项逐项设计、拆解、常规代码修改、Git 提交与本地目标分支合并，以及已配置目标的开始/完成通知；不扩展到推送、发布或部署。每项必须先通过工作流规定的审查、自测和合并闸门。
- 用户另行明确要求该版本交付时同步 TAPD 状态，视为授权该版本内已完成且可核实记录的状态修改；仍须核对当前记录、项目工作流和实际验收证据，逐步回读确认，不自动跳过尚未完成的验收阶段。授权不覆盖其他版本或记录。
- 上述授权不覆盖未确认需求、新增业务规则、认证/权限/敏感数据处理变更、数据库迁移、新依赖或外部服务、生产操作。遇到这些情形，先完成可独立处理的部分，再就具体变更请求授权。

不得仅因 AI 自己生成方案就视为获得批准；执行依据必须是用户的明确指令及其覆盖的范围。
