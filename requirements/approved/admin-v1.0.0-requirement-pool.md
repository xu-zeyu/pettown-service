## 竞品调研与取舍

资料访问日期均为 2026-11-05。Strapi 管理后台提供管理员和终端用户管理、RBAC、内容管理与审计日志；Appsmith 提供用户、角色、细粒度权限和审计；Metabase 展示数据看板及看板级访问权限。可借鉴的共性是：先有身份和权限边界，再开放业务数据；关键管理操作需可追溯；看板应受权限控制。首版仅借鉴这些原则，不复制 CMS、低代码平台或 BI 平台的通用构建能力。

## v1.0.0 必做需求详述

### A01 管理员登录、会话与改密验收（P0，96）

场景：已授权管理员进入后台、查看本人信息并安全退出。范围：接入现有用户名、密码、短信验证码登录，当前账号/权限、菜单、退出和首次/重置后改密；错误凭证、停用账号、过期会话有明确反馈。验收：未认证访问受保护资源被拒绝；改密后旧会话失效；不在页面或日志暴露密码、验证码或 Token。依赖：现有 `/mng/auth` 接口及短信服务可用。权限/数据：仅管理员身份数据，令牌不得持久明文存储。待确认：短信发送渠道及失败处理、会话时长和前端交付仓库。

### A02 管理员账号与角色权限闭环验收（P0，96）

场景：授权人员新增/停用管理员、分配角色与权限。范围：复用现有账号、角色、权限接口，提供列表、详情、维护与授权界面；菜单可见性与服务端鉴权一致，防止越权授予。验收：不同角色仅能执行其权限内动作；停用/撤权后重新访问受限；不可删除或改写内置权限造成失控；关键错误有可理解提示。依赖：现有 `/mng/system`、`/mng/role`、`/mng/permission` 能力。权限/数据：管理员联系方式与授权关系受限显示/修改。待确认：正式角色模板、谁可授予最高权限、账号删除策略。

### A03 管理端基础工作台与权限导航（P0，88）

场景：管理员通过浏览器完成 v1 必做任务。范围：登录页、统一布局、权限菜单、账号/角色/权限页面、终端用户与宠物只读页面、审计查询入口；标准空态、加载、错误和无权限反馈。验收：不同权限登录后只显示可访问入口；直接输入无权路径仍被前后端拒绝；核心任务可从导航抵达并完成。依赖：A01–A02、A04–A06 的接口；前端代码位置待确认。权限/数据：不在浏览器缓存敏感明文。待确认：前端项目、设计规范、浏览器支持范围。

### A04 终端用户查询与详情（P1，79）

场景：运营或客服根据账号标识定位用户。范围：分页查询、按 ID/完整手机号精确查找、查看 ID、来源及必要脱敏联系方式；不提供修改、禁用或密码重置。验收：无权限者不能访问；列表分页稳定；不存在/无权的结果和错误可区分而不泄漏其他敏感数据；手机号默认脱敏。依赖：现有 `user_account` 模型，新增受控管理端查询能力。权限/数据：单独的用户只读权限、个人信息最小显示。待确认：实际客服角色、手机号可见级别、数据保留规则。

### A05 宠物查询与归属核查（P1，79）

场景：运营核对用户反馈的宠物记录。范围：按宠物 ID、归属用户 ID 查询，分页展示名称、种类、归属与创建信息；不提供编辑、删除或审核。验收：无权限者不能访问；能从宠物定位归属用户；不存在记录有明确空态；大数据量分页可用。依赖：现有 `pet` 表和服务，新增管理端只读查询接口。权限/数据：独立的宠物只读权限；归属信息仅限授权角色。待确认：是否需要更多宠物字段、搜索条件和数据量。

### A06 关键管理操作审计与检索（P1，78；风险门槛列入必做）

场景：管理员追溯谁在何时进行了登录、账号状态/角色/权限变更。范围：记录操作者、动作、对象、时间、结果和请求追踪 ID；按时间、操作者、对象分页检索；敏感字段脱敏，不记录密码、验证码、Token。验收：成功和失败的关键变更可查；普通管理员不可更改审计记录；无权者不能查询；审计写入失败时不静默丢失关键变更。依赖：现有 `@Log`/日志基础设施，但需确认是否满足持久与检索。权限/数据：独立审计查看权限及保留策略。待确认：审计存储和保留时长、失败时阻断还是告警、可见角色。
